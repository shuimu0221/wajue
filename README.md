## 三十秒版

从质谱图推断分子的化学结构。每个分子给几张 MS/MS 谱，要输出最多 25 个候选结构的 SMILES，按可信度排序。

**做法不是"让模型直接写出分子"，而是"先找候选、再排序"**——因为评分只看正确答案排第几。

**当前状态**：管线跑通，本地基线 0.7581；结构库已扩到 72 万；class 2 从 0 提到 0.2193。**最大缺口是 class 3（全新结构），目前为 0。**

---

## 1. 题目

### 1.1 任务

| 项 | 内容 |
|---|---|
| 输入 | 每个 `molecule_id` 下 1–16 张 MS/MS 谱（中位 **3**），全部 Bruker timsTOF |
| 输出 | **≤25 个 SMILES**，按可信度降序，分号连接 |
| 判分 | **MRR@25**：只算第一个命中的位置，`1/rank`。位置 1 = 1.0，位置 2 = 0.5，位置 25 = 0.04 |
| 规模 | ~1,500 张谱 / **~400 个分子**，单同位素质量 157–1,159 Da（中位 348） |
| 加合物 | 固定 **10 种**，无二聚体 |

### 1.2 判等方式

你的 SMILES 和答案都经过 **RDKit 2026.03.3 的 tautomer 规范化**，取 InChIKey 前 14 位比较。

**含义**：立体化学、互变异构形式写错**不扣分**，骨架对了就得分。

### 1.3 三类难度（官方定义，占比隐藏）

| 类别 | 定义 | 我们的现状 |
|---|---|---|
| **class 1** | 结构在公开谱库里有参考谱 → 相似度检索可找到 | **0.7581** |
| **class 2** | 无公开谱，但结构在 PubChem / COCONUT 里 → 数据库检索可达 | **0.2193** |
| **class 3** | 结构**完全不在 PubChem** → 必须 de novo 预测 | **0.0000** |

### 1.4 硬约束

- **推理时断网**，CPU / GPU 各 **9 小时**
- 每天 **5 次**提交，最终只计 **2 次**
- 必须通过 Kaggle Notebook 提交，文件名为 `submission.csv`
- 允许自由公开的外部数据和预训练模型

### 1.5 竞争态势（2026-11-20 抓取）

5,591 支队伍。分数高度压缩：

| 分位 | 分数 |
|---|---|
| 榜首 | 0.552 |
| p90 | 0.492 |
| **中位** | **0.440** |

**0.44–0.50 之间挤了绝大多数队伍，真正的区分度只有最后 0.05。**

## 2. 我们的方案

### 2.1 核心判断

**这是一道"候选生成 + 排序"题，不是端到端生成题。**

理由：MRR 只看正确答案排第几。所以只要候选里**有**正确答案，剩下的就是排序问题；候选里没有，再好的模型也救不回来。

因此投入顺序是：
```
候选覆盖（有没有）  >  排序质量（排第几）  >  端到端生成（class 3）
```

### 2.2 五段流水线

```
test.parquet
   │
   ├─① 中性质量推算（10 种加合物，多谱聚类取中位）
   │
   ├─② 候选池检索（质量窗口）
   │      结构池 720,158 = train 275,301 + COCONUT 470,226 + NPAtlas 32,550
   │
   ├─③ 多通道打分
   │      a. 谱库检索   cos + 中性丢失 + analog 传播   ← 已完成
   │      b. 指纹模型   谱 → 2048 位指纹 → 候选打分     ← 待做（最高优先）
   │      c. 前向模型   "候选会碎成什么"                ← 待做
   │
   ├─④ 重排（分子内 rank 归一化 + LightGBM ranker）
   │
   └─⑤ 出口（按 InChIKey14 去重、≤25、每分子恰好一行）
```

### 2.3 关键设计：按谱证据分流

**实测发现：无差别合并大池会拖累 class 1（0.7581 → 0.7111）。**

所以按「谱库里有没有相似参考谱」决定用哪个池：

| 情况 | 用什么池 | 理由 |
|---|---|---|
| 谱库里有高相似参考谱（cos ≥ 阈值） | **小池**（train 27.5 万） | 精度优先，候选少（中位 33） |
| 找不到 | **大池**（合并 72 万） | 覆盖优先，候选多（中位 69） |

代码已实现：`a_candidates.route_by_spectral_evidence()` + `build_candidates_routed()`。
**阈值尚未校准**——需要能代表 class 2 的验证集（见 §4.3）。

## 3. 已完成

### 3.1 数据与验证基础

| 事项 | 结果 |
|---|---|
| 数据核实 | train 2,539,608 行 × 18 列，test 1,213 行 × 12 列，**与官方清单完全一致** |
| **泄漏核查** | **可见 test 的 1,213 张谱 100% 出现在 train 里**（内容指纹全量比对） |
| 中性质量推算 | 10 种加合物，全部还原到同一中性质量；400/400 在 **5 ppm** 内 |
| 验证集 | 两个：合成空间 400 分子、**天然产物 390 分子**（更接近真实测试集） |
| 评测/提交自检 | `common` / `chem` / `a_eval` / `a_submit` 全部 PASS |

**⚠️ 最重要的一条**：可见的 `test.parquet` 是训练集的抽样，**在它上面算分必然虚高**。本地评测必须从 `train.parquet` 切分。

### 3.2 实测结果

**基线（390 个天然产物分子）**

| + NPAtlas | 32,550 | 天然产物补充 |
| **合并** | **720,158** | 候选/分子 33 → 69 |

**class 2 模拟**（148 个"真值确实在 COCONUT 里"的分子，无谱证据，仅按质量排序）

| 配置 | MRR@25 | R@1 |
|---|---|---|
| 无 COCONUT | **0.0000** | 0% |
| **有 COCONUT** | **0.2193** | 13.5% |

### 3.3 四条硬结论

| # | 结论 | 证据 |
|---|---|---|
| 1 | **COCONUT 有净价值**：class 2 从 **0 → 0.2193** | 148 分子模拟 |
| 2 | **但不能无差别合并**：class 1 从 0.7581 → **0.7111**（−0.047） | 候选数 33→69 |
| 3 | **分子式注释没用**：oracle 实验 0.2153 vs 0.2193，零收益 | 窗口内分子式本就不重复 |
| 4 | **class 2 的瓶颈是同分异构体** | 同式同质量，只能靠碎片模式区分 |

### 3.5 一个负面结果（值得记住）

LightGBM ranker **没有上线**：OOF MRR 0.8801 vs 线性基线 0.8727，**Δ = +0.0074，未超噪声阈值 0.025**。

原因：训练信号太弱（只有 400 个 query），且线性基线已经很强。**等有了 3–4 个真正独立的通道之后再上 ranker 才有意义。**

### 4.3 关于「分流阈值校准」为什么是 P0

现有天然产物验证集的 **390 个真值全部来自 train**（因为它是从 train 抽的），所以：
- 所有分子都能在小池里找到答案
- 任何走大池的分子**只承担代价、拿不到收益**
- 分流的收益**无法被这个验证集测出来**

要解决，需要构造真值**只在 COCONUT、不在 train** 的样本。目前缺这类数据——这是 W2 的方法论缺口。

### 4.4 指纹模型：本机没 GPU 怎么办

已实测本机吞吐（Intel 8 核，torch 2.15 CPU）：

| 数据量 | 1 epoch |
|---|---|
| 全量 254 万 | **约 4 小时** |
| 10% 子集 | 约 0.4 小时 |
| 2% 子集 | 约 0.1 小时 |

**结论：能训，但正式训练应放 Kaggle 免费 GPU（每周 30 小时，快 10–30 倍）。**

关键：**9 小时限制只管推理，不管训练。** 标准做法是离线训练 → 权重上传成 Kaggle Dataset → 提交 notebook 只做推理（1,213 张谱，CPU 几秒完成）。

**建议路径**：先用 2% 子集跑 3–5 epoch，确认 loss 在降、逐位 AUC 有信号；通了再上全量。

## 5. 必须记住的纪律

| # | 纪律 | 理由 |
|---|---|---|
| 1 | **可见 test.parquet 不能用来算分** | 它是训练集抽样，实测 100% 重叠 |
| 2 | **本地 CV 是唯一可信信号** | 榜只有 ~124 个分子，单分子变动让榜分跳 0.004 |
| 3 | **外部数据必须提前挂 Kaggle Dataset** | 推理断网 9 小时 |
| 4 | **验证集按 `cand_key` 排除，不按来源库** | 同一化合物跨库重复 |
| 5 | **提交列名是 `molecule_id,smiles`** | 不是 `smiles_list` |
| 6 | **特征重要度一边倒（>90%）就是泄漏** | 我们踩过：`f_cos_self` 占 94.9%，MRR 虚高到 1.0 |
