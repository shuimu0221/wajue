## 1. 最大的陷阱：可见的 test.parquet 不是测试集

官方 data-description 原文：

> **Note**: the file you see is comprised of examples from the training dataset; it will be
> replaced by the hidden test set during re-run, and will be approximately the same size.

含义，按后果排序：

1. **在可见 `test.parquet` 上算任何分数都是假的**，接近满分。
2. 可见 test 的 `spectrum_id` **可能直接出现在 `train.parquet` 里**，答案就在手边。
3. 你**不能**用它的分布做任何统计结论——它只是"规模相近的样本"。

**正确的做法**：从 `train.parquet` 自己切 holdout。可见 test 只用来：
- 确认文件 schema 和列名（这个是真的）
- 确认规模（~1,500 谱 / ~400 分子）

`a_load.py --check-leak` 会验证第 2 条：把可见 test 的 `spectrum_id` 和
`ms2_mzs` 指纹与 train 比对，报告重叠率。**第一天就要跑这个，亲手确认，不要信我的话。**

## 2. 为什么不能随便切折

| 陷阱 | 后果 | 修法 |
|---|---|---|
| 按 `ingest_lib` 过滤做 holdout | 同一化合物跨库重复（原文："the same compound measured independently by several libraries remains"）→ 答案还留在索引里 | **按 `cand_key`（InChIKey14）排除** |
| 随机切分子 | 同骨架近系物分散在 train/val，analog 传播白送分 | Murcko 骨架分折 |
| 不模拟 class 3 | 随机切里 class 3 比例远低于真实值 | `mimic` 方案 |
| 用 `enveda-180` 当验证 | 它是**合成类药**化学空间，与测试集（天然产物）差异大 | 验证要看 `enveda-np-examples` 和 `riken` 方向 |

原文明确说 `enveda-np-examples` 的 250 个化合物"deliberately common and appear in other
libraries too, so you can compare"——**它就是官方给的域适配对照集**，最适合当验证锚点，
但也正因为它到处都有，必须严格按 `cand_key` 排除。

## 3. 三种折方案

`get_folds(scheme=...)`：

### 3.1 `random` — 只用来 debug
随机 5 折。不用于任何结论。

### 3.2 `scaffold` — 判断"新骨架"能力
按 Murcko 骨架分折（`rdkit.Chem.Scaffolds.MurckoScaffold`）。小类合并。

### 3.3 `mimic`（**默认**）

对每个验证分子，显式裁剪候选池，模拟它所属类别：

| `sim_type` | 构造 | 目标占比 |
|---|---|---|
| 1 | 该分子本身在候选池里 | ~10% |
| 2 | 移除该分子，保留同骨架 analog | ~38% |
| 3 | 移除该分子**及所有 Tanimoto > 0.5 的近邻** | ~52% |

> ⚠️ 这里的 10/38/52 是**我们的假设**，不是官方数字。官方明确说类别分布
> "hidden for the duration of the competition"。所以 `mimic` 的权重应该是**可调参数**，
> 并且最终决策要同时看 `scaffold` 折的结果。**不要把这组比例当成事实引用。**

必须有的断言：

```python
def assert_no_leak(index, holdout_keys):
    """断言 holdout 的结构已从谱库索引排除，且精确谱匹配返回空。
    任一失败 → 抛异常。不许静默继续。"""
```

## 4. 分层指标：一个 MRR 不够

| 指标 | 含义 | 用途 |
|---|---|---|
| `mrr` | 总 MRR@25 | 唯一能对榜分的数 |
| `mrr_by_sim_type` | 按 1/2/3 拆 | 诊断主因 |
| `recall@1/@5/@25` | 命中率 | 分清"召回不够"还是"排序不对" |
| `cand_in_pool` | 答案是否在候选池 | **召回上限**，硬天花板 |
| `best_pos_mass_rank` | 正确答案的质量名次 | 候选池够不够 |

**判读规则**：

- `cand_in_pool` 高、`recall@1` 低 → **纯排序问题**，投 D
- `cand_in_pool` 低 → **召回问题**，投 A（候选池）+ B（生成）
- `mrr` 涨但 `mrr_by_sim_type[3]` 不涨 → 在优化已有的，对私榜无意义

## 5. 对照组

| 基线 | 是什么 | 期望 |
|---|---|---|
| `B0_random` | 按质量偏差随机排 | ~0.10 |
| `B1_public` | 公开基线（榜单中位 0.440 附近） | 0.44–0.49 |
| `B2_prev` | 上一次自己的提交 | — |

`B1_public` 必须**先在本地复现出与榜分同量级**的数，否则验证协议和评测口径不一致。

## 6. 噪声与决策规则

- 单折 MRR 标准误 ≈ `0.5/sqrt(n)`；n=400 时约 **±0.025**（比想象的粗得多）
- **ΔMRR < 0.02 的改动视作噪声**，除非三个 seed 同向
- 公开榜 ~124 个分子（31% × 400）：
  - 一个分子从 rank 2 升到 rank 1 → 榜分 +0.5/124 ≈ **+0.004**
  - 0.492 → 0.500 只需两个分子翻盘 → **完全在噪声内**
- 最终提交选 **多 seed CV 最稳**的两个，不选 LB 最高的两个
