## 1. 任务定义（原文）

> Your task is to identify the chemical structure of an unknown molecule from its tandem mass
> spectrometry (MS/MS) spectra. For each molecule you submit up to 25 candidate structures as
> SMILES, ranked best-guess first. **Predictions are made per molecule, not per spectrum**, so
> you must aggregate the evidence from all of a molecule's spectra into one ranked list.

化学空间：天然样品（植物 / 哺乳动物 / 微生物）相关——确认的天然产物、假想天然产物、
天然产物类似物，以及"可能出现在自然界"的合成分子。

## 2. 文件清单（原文）

| 文件 | 内容 |
|---|---|
| `train.parquet` | ~2.5M 张 MS/MS 谱，~275k 个唯一结构，**带结构标签**。一行一张谱 |
| `test.parquet` | 待识别。**你看到的是训练数据里的样本**，rerun 时替换为隐藏测试集，规模相近 |
| `sample_submission.csv` | 格式正确的提交样例 |

> ⚠️ **这是本赛最关键的一条工程事实**：公开的 `test.parquet` 取自训练集。
> 在它上面算分**必然虚高**。本地验证只能从 `train.parquet` 里切。

## 3. 列车数据 schema（原文表格）

`test.parquet` 12 列：

| 列 | 说明 |
|---|---|
| `molecule_id` | 匿名化合物 ID，**预测单位** |
| `spectrum_id` | 谱唯一 ID |
| `ms2_mzs` | 碎片 m/z 数组 |
| `ms2_normalized_intensities` | 对齐的强度数组，**基峰 = 1.0** |
| `base_peak_intensity` | 归一化前最大峰的原始强度（越强噪声越少） |
| `adduct` | 母离子加合物 |
| `ionization_mode` | `positive` / `negative` |
| `instrument_type` | 恒为 `timsTOF` |
| `precursor_mz` | 实测母离子 m/z |
| `collision_energy_ev` | **list**。`[20]` = 一次采集；`[20,40,60,80]` = 多次采集合并 |
| `collision_energy_orig` | 原始记录值 |
| `collision_energy_orig_units` | 测试集恒为 `eV` |

`train.parquet` 另加 8 列：

| 列 | 说明 |
|---|---|
| `normalized_smiles` | **标签**。RDKit 标准化 SMILES |
| `inchikey` / `inchikey14` | InChIKey 及其前 14 位（2D 骨架） |
| `molecular_formula` | 中性结构分子式 |
| `ingest_lib` | 来源库 |
| `adduct_orig` | 标准化的加合物字符串 |
| `precursor_error_ppm` | 实测 vs 标签推出的 ppm 误差，**未清洗，可当标签质量信号** |
| `num_peaks` | 碎片峰数 |

> `collision_energy_ev` 是"设计成与测试集对齐"的列。**模型要吃碰撞能就用这一列**（原文明确建议）。

## 4. 判分：MRR@25（原文）

$$\mathrm{MRR@25}=\frac1U\sum_{u=1}^U\frac1{\mathrm{rank}_u}$$

- `rank_u` = 你的列表里**第一个**正确结构的位置
- 一个分子只有一个正确答案，**只算第一次命中**
- 位置 1 = 1.0，位置 2 = 0.5，位置 25 = 0.04，未命中 = 0

**判等规则**：你的 SMILES 和答案都过 RDKit **tautomer canonicalization（pin 在 2026.03.3）**，
取 InChIKey 第一段（InChIKey14）比较。**立体化学和互变异构形式错了不扣分。**

原文例子：葡萄糖的两个写法（含 / 不含立体化学）都归一到同一个 InChIKey14
（`WQZGKKKJIJFFOK`），得分相同：

```
OC[C@H]1OC(O)[C@H](O)[C@@H](O)[C@@H]1O
OCC1OC(O)C(O)C(O)C1O
```

> 评测页**没有**提到"重原子组成不同直接判否"这条。上一版草稿里的这条是我推断的，
> **原文没有依据**。不过 InChIKey14 天然编码了分子式骨架，实践上等价效果，可以继续当预筛用，
> 但不要声称这是官方规则。

### 提交格式（原文）

```
molecule_id,smiles
m_0014ef,CC1=CC(=O)C=CC1=O;OC(=O)c1ccccc1O;CN1C=NC2=C1C(=O)N(C)C(=O)N2C
m_004d06,NCCc1ccc(O)cc1;CC(=O)Nc1ccc(O)cc1;OCC(O)CO
```

拒绝条件（原文）：
- 缺 `molecule_id` 或 `smiles` 列
- 空文件
- 任一列含 null
- `molecule_id` 重复
- 任一分子超过 25 个分号分隔的猜测

少于 25 个可以，**错猜除了占位没有额外惩罚**。

## 5. 测试集构成（原文）

- ~1,500 张谱 / ~400 个分子，每分子 1–16 张（中位 3），**全部 Bruker timsTOF**
- 单同位素质量 157–1,159 Da（中位 348）
- 三类新颖度，**分布和归属全程隐藏**：

| Class | 定义 |
|---|---|
| **1** | 结构在公开谱库里有参考 MS/MS 谱 → 可用谱相似度找到 |
| **2** | 无公开谱，但结构在 **PubChem 或 COCONUT** 里 → 可用数据库检索到达 |
| **3** | 结构**完全不在 PubChem** → 必须 de novo 预测 |

- 清洗极轻：只删了"母离子与结构+加合物不一致"的谱、"基峰 < 1000 raw counts"的谱，
  以及 precur + 2 Da 以上的峰
- **测试集只用这 10 种加合物**：

```
[M+H]+  [M+NH4]+  [M-H2O+H]+  [M-2H2O+H]+  [M+Na]+
[M+K]+  [M-H]-    [M-H2O-H]-  [M+CH2O2-H]-  [M+Cl]-
```

训练集还有更多（含二聚体），但**测试集没有二聚体**。

## 7. 官方推荐的前处理（原文列出的"common curation methods"）

1. **相对强度下限**：2% / 1% / 0.1% 都常见
2. **丢掉高于母离子的峰**（+1–2 Da 容差）
3. **最少峰数**：少于 ~5–6 个峰的谱信息量太低
4. **最大峰数**：取强度 top-N，常用 N=128；
   **经典库检索变体：每 50 Da 窗口保留 top ~6 峰**（保留低质量碎片）
5. **去同位素峰**：每个碎片上方 ~1.0033 Da 的 C13 伴峰
6. **强度变换**：sqrt 或 log
