# W1 失败分析（2026-11-20）

> 数据：400 个分子（`data/interim/dev_labels.parquet`），候选池含真值，
> 检索时**排除查询谱本身**（保留同化合物的其他谱），模拟 class 1 的情形。
> 复现：`python code/d_baseline.py --cand data/candidates/candidates_with_truth.parquet \
>          --feat data/features/feat_search_with_truth.parquet --w-nl 0.5 --w-mass 0.1`

## 1. 结论先行

| 项 | 值 |
|---|---|
| **MRR@25** | **0.8730** |
| 排第 1 | 313 / 400（**78.2%**） |
| 排第 2–5 | 79 |
| 排第 6–25 | 3 |
| **未进 25（召回失败）** | **0** |

**MRR 缺口 1.0 → 0.8730 = 0.1270，全部来自排序，没有一分来自召回。**

这个结论**只在这个开发集上成立**，因为真值本来就在池里（见 §4 的重要限制）。

## 2. 失分构成

| 来源 | 损失（MRR 总量） | 占比 |
|---|---|---|
| 排 2–5 名 | 43.27 / 400 = **0.1082** | **85%** |
| 排 6–25 名 | 2.65 / 400 = 0.0066 | 5% |
| 完全未命中 | 0.00 | 0% |

**排序问题几乎全部集中在「第 1 名被错占」**：把第 2 名提到第 1 名，MRR 直接 +0.108。

## 3. 错排的分子长什么样（87 个）

| 特征 | 值 |
|---|---|
| 分数差 `top_cos − truth_cos` 中位 | **0.0687** |
| 差值 < 0.05（接近平局） | **29 / 87（33%）** |
| 答案 `truth_cos < 0.5`（几乎没有谱证据） | 9 / 87 |
| 答案排名中位 | 2 |

**典型错排**：正确答案 cos=0.925 排第 3，第一位 cos=0.952。差 0.027。
这是**近似同分**问题，不是「答案明显不对」的问题——正是 learning-to-rank 的主场。

## 4. 候选数的影响（可操作的杠杆）

| 候选数 | n | MRR | 排第 1 比例 |
|---|---|---|---|
| < 50 | 127 | **0.915** | 85.8% |
| 50–100 | 104 | 0.863 | 76.0% |
| 100–200 | 107 | 0.842 | 72.9% |
| 200+ | 62 | 0.857 | 75.8% |

候选越少，MRR 越高。**收紧质量窗口是免费的收益**——
但真实测试集里收紧会同时损失召回（class 2/3 的答案会更早被排除）。
所以这个杠杆**只能在 class 1 上用**，不能推广。

## 5. 通道消融（真实测量）

| 配置 | MRR@25 |
|---|---|
| 仅质量偏差（B0） | 0.1379 |
| cos only | 0.8603 |
| **cos + nl 0.5** | **0.8715** |
| cos + nl 0.5 + mass 0.1（当前基线） | **0.8727** |
| cos + nl 0.3 + mass 0.2 | 0.8543 |
| cos + nl 0 + mass 0.5 | 0.7686 |

### 两个反直觉的发现

**（1）质量项用「分子内 rank 均匀铺开」是有害的。**
`f_mass = 1 − (rank−1)/n` 在 w=0.2 时把 MRR 从 0.8603 拉到 0.8337（−0.027）。
原因：候选池每分子中位 79 个，rank/n 把 0–1 摊得极开，噪声被放大。
换成 `exp(−|ppm|/2)` 后变成 +0.0012（噪声级，但至少不伤）。

> 交接给 D：**任何特征进线性融合前，先确认它不是「均匀铺开型」的 rank 变换。**

**（2）nl（中性丢失）是唯一有实质贡献的第二通道**（+0.011）。
cos→cos+nl 是 0.8603→0.8715。其余质量项基本是噪声。

## 6. ⚠️ 这个数字不能当榜分用

三条限制，按严重程度：

1. **化学空间不匹配。** 400 个分子**全部来自 `enveda-180`**，是合成类药化合物
   （94/400 含 F、44 含 Br/Cl），官方明确说它与测试集（天然产物）是
   "a different region of chemical space"。**天然产物的谱更碎、更复杂**，
   检索和指纹模型的表现会不一样。

2. **全是 class 1。** 真值都在池里，所以「召回失败 = 0」是构造出来的。
   真实测试集 class 2/3 约占一半，那些分子**在 train 结构池里根本没有**。

3. **谱是同一台仪器同一批次**（timsTOF，Enveda 自己的流水线）。
   真实测试集的谱虽然是同仪器，但不是同一采集协议。

**所以 0.8730 的正确读法是「class 1 上的排序上限」，不是「榜分预估」。**

## 7. 对 W2 的行动指令

| 优先级 | 动作 | 谁 | 依据 |
|---|---|---|---|
| **P0** | 接入 **PubChem + COCONUT** 结构池 | A | 没有它，class 2/3 的召回是 0，而这占真实测试集约一半 |
| **P1** | 上 LightGBM ranker，特征 = cos/nl/ppm/候选数 | D | 33% 错排是 0.05 以内的平局，线性组合分不开 |
| **P2** | 指纹模型（C） | C | 唯一能在「无参考谱」时给结构打分的通道 |
| **P3** | 收紧质量窗口 | — | 只在 class 1 有效，**不要全局用** |

**一句话**：本地排序已经做得不错（78% 直接命中），但**真实比赛的瓶颈在召回**，
不在排序。W2 的重心应该是候选池，不是 ranker。
